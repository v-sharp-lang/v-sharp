# V# feature matrix — C# 13 classification

Every clause of the C# 13 specification is classified here. `Status` is one of:

| Status | Meaning |
| --- | --- |
| `in` | In scope. Must reach semantics, lowering, bytecode, execution and tests. |
| `partial` | In scope with a documented restriction, stated in the row. |
| `out` | Excluded. The row states the exact semantic dependency on the omitted object model. |

The exclusion principle is narrow and mechanical: a construct is `out` only when its
semantics **require** user-declared reference types with inheritance, virtual dispatch or
member overriding. A construct is not excluded merely because C# happens to express it
with a class, and it is not included merely because it is convenient.

`Lowering` names the JVM representation. Two carriers recur:

* **synthetic holder** — a `final` class synthesised per source file (or per declared
  `static class`-like grouping) holding `static` methods and `static final` fields. V#
  never emits a user-visible instance type.
* **runtime helper** — a call into `vsharp.runtime`, e.g. `VsIndex`, `VsRange`,
  `VsSlices`, `VsTupleN`, `VsFormat`.

`Tests` names the suite that owns the feature. `-` means the suite does not exist yet;
that is a scheduling fact, not a gap in the classification.

**This matrix classifies the language, not the build.** `Status` states whether a construct
is in V#'s scope and what its semantics and intended JVM representation are. It is not a
per-stage progress report: a row may be `in` while the backend still refuses one of its
shapes. The authoritative, current statement of what the backend emits — and the explicit
list of forms that throw instead — is [`BYTECODE.md`](BYTECODE.md#forms-that-refuse-to-emit),
kept in step with the implementation.

| Static field initializers | `in` | Run in declaration order before the holder's first use, as C#'s implicit static constructor does. | `const` declarations (fields and locals) | `in` | A `const` field is folded on demand by a dedicated pass that runs after every declaration exists and before expression binding, so its initializer is bound and folded by the *same* [ConstantEvaluator] a local const uses. It therefore admits the whole constant surface: `int.MaxValue`, a read of another `const` in the same type, another type or another file, enum members and casts of them, `checked`/`unchecked`, string concatenation of string constants, and every folding operator. Failures are C#-exact rather than compiler-flavoured: `1 / 0` and `5 % 0` report `VS0020`, an overflow reports `VS0220`, a cycle such as `const int A = B; const int B = A;` reports `VS0110` (CS0110) instead of recursing, and an initializer that binds but is not a constant expression - a call, a concatenation with an enum operand - reports `VS0133` (CS0133), naming the constant. **Divergence:** the same CS0133 rule is *not* enforced on a `const` **local**, which still accepts a non-constant initializer and computes it at run time. A local's folded value is not carried on its symbol, so the evaluator cannot fold a read of one, and a gate there would reject the valid `const int Half = Max / 2;`. Correct programs are unaffected; only a program C# would reject is accepted. | Every read is replaced by the folded value; a `const` field has no run-time storage. | `semantic.constants`, `backend.generation` |
| Arrays, jagged | `in` | Creation, element read/write, `Length` and `foreach` to any nesting depth. | Arrays, rectangular (`int[,]`) | `partial` | Declaration, creation, multi-index element read/write and `Length` (the total element count, as in C#). Multi-dimensional array *initializers* are not lowered: `int[,] m = {{1,2}}` keeps its parse diagnostic. | `multianewarray` for creation, one `aaload` per leading index for access, and `VsArrays.length` for `Length`, which `arraylength` would under-report. | `types`, `backend` |
| Pointers, `unsafe`, `stackalloc`, `fixed` | `out` | The JVM has no verifiable raw pointer model; `java.lang.foreign` is a different, non-equivalent surface. Excluded for verifiability, not for the object model. | — | — |
| `ref struct`, `Span<T>`, `ReadOnlySpan<T>` | `out` | Depends on stack-only lifetime rules the JVM verifier cannot express. Revisit only if a lifetime analysis proves soundness without runtime support. | — | — |
| Classes, interfaces, inheritance, `virtual`/`override`/`abstract`/`sealed` members, constructors, properties, indexers, events, delegates as user types, generic variance on user types | `out` | These *are* the omitted object model: they require user-declared reference types with a vtable and member overriding. This is the project's defining exclusion. | — | — |
| Anonymous types | `out` | Each is a synthesised class with overridden `Equals`/`GetHashCode`/`ToString` — object-model dependent. Tuples cover the need. | — | — |

## 3. Conversions

| Feature | Status | Semantics | Lowering | Tests |
| --- | --- | --- | --- | --- |
| Implicit numeric, enum, nullable lifting, tuple, constant-expression conversions | `in` | C# tables verbatim, including `int` constant to `byte` when in range. | Primitive conversion opcodes. | `conversions` |
| Explicit numeric conversions, `checked`/`unchecked` | `in` | `unchecked` truncates; `checked` throws `OverflowException`. | `Math.*Exact` under `checked`; plain opcodes otherwise. | `conversions` |

| Reference conversions, `is`/`as`, dynamic | `partial` | `is`/`as` fully. `dynamic` is `out`: it requires the runtime binder and call-site caching over the object model. | `instanceof`/`checkcast`. | `conversions` |

## 4. Expressions

| Feature | Status | Semantics | Lowering | Tests |
| --- | --- | --- | --- | --- |
| All arithmetic, relational, logical, bitwise and shift operators | `in` | C# precedence, associativity, overflow and shift-count masking. `==`/`!=` over two `string`-typed operands is value equality as C# defines it, decided by the *static* type, so `(object)a == (object)b` stays reference equality. | Direct opcodes; unsigned via `java.lang.Integer/Long` statics; `java.util.Objects.equals` for string equality, which is null-safe in exactly C#'s way. | `expressions`, `backend` |

| Null-conditional `?.`, `?[]` | `in` | The receiver is evaluated exactly once and the whole chain short-circuits: a null receiver skips every argument and every subsequent access. | `nameof`, `typeof`, `sizeof` (managed), `default`, `checked`/`unchecked` expressions | `partial` | `default`, checked contexts and `nameof` over a named entity are implemented; a nameless `nameof` operand reports `VS8081`. `sizeof` accepts C#'s safe predefined fixed-size types and reports `VS0233` for operands that would require `unsafe`. `typeof` has two carriers: over a module-path Java type it is a `java.lang.Class`, erasing constructed arguments exactly as the JVM does, so the value is directly consumable by reflective JDK APIs; over a V#-owned type it preserves source identity - qualified names, unbound generic definitions and tuple-name erasure - because signedness and nullability have no JVM class. | Index `^` and range `..` operators | `in` | `Index`/`Range` semantics, including bounds validation. | `VsIndex`, `VsRange`, `VsSlices`. | `runtime.indexrange` |
| Collection expressions `[a, b, ..spread]` | `in` | C# 12 collection expressions with spreads, target-typed to arrays and supported collection types. | Array construction or builder calls. | `expressions` |
| Lambdas over Java functional interfaces | `partial` | A lambda converts to any Java single-abstract-method interface (JLS 9.8) and is bound against that method's *substituted* signature, so `Predicate<string>`'s parameter is `string` rather than `object`. Both C# body shapes are implemented: an expression body, and a statement block bound under the lambda's own callable by the ordinary statement walk, so `return` conversions, definite assignment and end-point reachability come from one implementation rather than a lambda-specific copy - a block that does not return on every path reports `VS0161`, a value returned to a `void` target `VS0127`, and a local read before assignment `VS0165`. A block against an *open* return type is closed by what its `return` expressions produced, the statement-body counterpart of that rule. A block may declare locals and local functions of its own; the emitted method name is chosen when the body is declared, not renamed afterwards, so those symbols carry the final `Enclosing$lambda$n` prefix that capture analysis and class placement both decide by. A lambda captures the enclosing *variable* through the shared one-element cell V# already uses for local functions, so writes cross the boundary in both directions exactly as C# specifies - verified against a .NET 10 oracle - and captures lead the implementation method's parameters because `LambdaMetafactory` prepends them at the call site. A lambda no target type ever claims is refused with `VS20001`. A lambda passes *directly* to a wildcard-declared JDK parameter (`Comparator<? super T>`, `Predicate<? super T>`, `BiConsumer<? super K, ? super V>`): JLS 9.9's non-wildcard parameterization is applied where a lambda is typed (the design, moved there by that rule), so `Collections.Sort`, `RemoveIf`, `ForEach`, `Filter` and `Map.ForEach` all take a lambda from source while the *type* keeps its wildcards - which is what lets `Iterable<? extends CharSequence>` stay variant and admit a `List<string>`. `Stream.Map` works too: a type parameter that only a lambda body can supply stays open through inference and is closed by the bound body, so `Map(n => n.Length).ToList()` is a `List<int>`. A *static* generic method has no receiver to infer from, so a type parameter appearing only in the functional parameter is closed by the types the lambda **writes**: `Collectors.GroupingBy((string w) => w.Length)`, `Collectors.ToMap`, and the two-argument `GroupingBy(classifier, Collectors.Counting())` all bind and execute, with the body closing the remaining parameter through that rule. Writing the parameter type is the requirement there - an implicit `w => ...` in that position is typed only when some other argument or the enclosing call already fixed it - and a boxed carrier in a type-argument position *is* the keyword type, so a `Counting()` downstream collects into `Map<int, long>` and `IntStream...Boxed().ToList()` is a `List<int>`. Two overloads distinguished only by their functional parameter are separated by the lambda itself, exactly as C# §10.7/§12.6.4.4 and JLS 15.27.2 specify: a void-returning target accepts an expression body only when that expression is a statement expression, and when both still apply the value-returning target wins - so `ExecutorService.Submit(() => "done")` is the `Callable` and `Execute(() => log.Add(x))` the `Runnable`. Divergence: for a lambda whose body is a *void* call, C# and Java choose the `Runnable`; V# chooses the value target and reports `VS0029` (`void` cannot close its type parameter) rather than binding the body speculatively against every candidate. `Execute` expresses that case. | The body becomes an ordinary static method under the local-function `Enclosing$name` convention; the value is an `invokedynamic` bootstrapped by `LambdaMetafactory.metafactory` carrying the erased SAM descriptor, the implementation handle and the instantiated descriptor - javac's own shape. The instantiated descriptor boxes exactly the positions erasure left as references, so `BiConsumer<string,int>` is `(String,Integer)void` while `Predicate<string>.test` keeps its declared `boolean`. | `semantic.interop`, `semantic.lambda-scopes`, `backend` |
| Delegates, anonymous methods, lambda natural type, `params`/default parameters in lambdas | `out` | Excluded: a delegate is a reference type with instance state and virtual invocation, which is the object model V# omits. A lambda therefore has no type of its own and only a functional-interface target can give it one. | — | `semantic.lambda-scopes`, `api.compilation` |
| `Func`/`Action` built-in delegate types | `in` | The spelling denotes a JDK functional interface, never a synthesized delegate type: `Action` is `Runnable`/`Consumer`/`BiConsumer` and `Func` is `Supplier`/`Function`/`BiFunction`, by arity. The generic interfaces are used and never the primitive-specialised ones, because C# delegate semantics are generic and selecting by primitiveness would make one spelling denote two types. An arity the JDK has no counterpart for is refused rather than fabricated. Invocation `f(x)` lowers to the interface's single abstract method. *Multicast, `+=`/`-=` combination and user-declared `delegate` types remain out* - those need the object model. | `invokeinterface` on the SAM; a lambda target-types to it through `LambdaMetafactory`. | `semantics.lambda`, `backend.generation` |
| User-declared `delegate` types, multicast, events | `out` | Multicast delegates and events are reference types with instance state and invocation-list mutation — object model. | — | — |
| Query expressions (LINQ) | `out` | Desugars to extension-method calls on `IEnumerable<T>`/`IQueryable<T>`, generic interface hierarchies V# has no way to declare or implement without the object model. Extension methods themselves are `in`; the query syntax stays out because its target surface does not exist, not because the call form does. | — | — |
| `await`, `async` | `partial` | In scope as bounded-blocking sugar, reversing the earlier exclusion. `Task` **is** `java.util.concurrent.Future` and `Task<T>` is `Future<T>`, so a future from any JDK or third-party API is awaitable with the same keyword. An `async` callable starts its body on a virtual thread at the call and returns that task; `await` joins it, bounded by an architectural **60-second** limit that nothing can change, and rethrows the body's own exception unwrapped. C#'s awaiter protocol and state machine are *not* implemented - they are what needs the object model - and neither is observable to a program that only starts work and joins it. `await` works in any body, not only an `async` one, which is what makes the limit reachable from synchronous code; the cost is that a local cannot be named `await`. `async void` runs detached and logs an escaping failure. Restrictions, each diagnosed: `async` on a lambda or local function (`VS20016`), a return type that is not `Task`/`Task<T>`/`void` (`VS20014`), awaiting a non-task (`VS20015`), `ref`/`out`/`in` parameters (`VS20017`); no cancellation token and no `ConfigureAwait`. Details: [`ASYNC.md`](ASYNC.md). | Body emitted as a private `Name$async` method; declared name becomes a wrapper doing one `invokedynamic` to `Callable`/`Runnable` plus `VsAsync.run`; `await` is `VsAsync.await` plus the erasure cast. | `async` |
| Object/collection initialisers, `new` on classes, `with` on classes | `out` | Require user-declared reference types. Direct construction of module-path Java classes is interop rather than a V# object model. `new` on a V# user type and `with` are implemented for the positional `record struct` only (the design, §3), which needs no object model: its constructor and members are fixed by the declaration. | — | — |
| Method invocation, overload resolution, named and optional arguments, `params`, `ref`/`out`/`in` | `partial` | Full C# overload resolution including betterness rules and generic inference; `ref`/`out` declarations and calls bind and flow-analyse. Code generation supports `ref`/`out` arguments that are locals, plain parameters, pass-throughs of another `ref`/`out` parameter, static fields, instance fields and array elements of any rank, via one-element array cells. `in` stays by-value: readonly, but it does not observe mutations made through a `ref`/`out` alias to the same variable in the same call. | Static invocation; `ref`/`out` parameters become one-element array descriptors and the caller copies the cell in (`ref`) and back after the call. Static-field places use `getstatic`/`putstatic`, instance fields use a spilled receiver plus `getfield`/`putfield`, and array elements use spilled receiver+indices plus the JVM rank-descent chain and `Xaload`/`Xastore`. `in` uses the plain scalar descriptor. | `overloads`, `api.compilation`, `backend` |

## 5. Statements

| Feature | Status | Semantics | Lowering | Tests |
| --- | --- | --- | --- | --- |
